# Mnemosyne

Кросплатформний десктопний простір для роботи з проєктами та coding-agent. Застосунок написаний на Rust і розрахований на Windows 10/11 та Linux.

## Можливості першої версії

- Додавання наявних папок і створення папок проєктів.
- Прибирання проєкту зі списку з підтвердженням; папка та її файли не видаляються, але локальні чати прибраного проєкту втрачаються.
- Вбудований перегляд та редагування Markdown і текстових файлів проєкту; Markdown-перегляд розбирає CommonMark із таблицями, списками завдань та закресленням. PNG/JPEG/GIF/WebP/BMP можна переглядати в застосунку, PDF відкривається у системному переглядачі.
- Створення Markdown-шаблонів плану та звіту у папках `docs/plans` і `docs/reports`.
- Пошук файлів у списку проєкту без сканування залежностей і каталогів збірки.
- Окремі чати в кожному проєкті зі збереженням історії локально.
- Файл стану застосунку записується через тимчасовий файл і атомарну заміну, щоб збій запису не залишив частково перезаписану історію.
- Перейменування та експорт чатів у Markdown; очищення історії або видалення чату з підтвердженням.
- Markdown-відповіді агента відображаються з форматуванням блоків, заголовків, списків і таблиць.
- Відповідь Claude Code показується в реальному часі; запит можна скасувати.
- Під час роботи показується назва активного інструмента Claude Code.
- Вибір сімейства Claude Code (Sonnet/Opus/Haiku) з маршрутизацією у FreeLLMAPI.
- Ліміт контексту від 5 до 40 останніх запитів або вся історія; локальна історія не обрізається.
- Прикріплення файлів і зображень до повідомлень.
- Підключення до FreeLLMAPI через його локальний OpenAI/Anthropic-сумісний API.
- Робота через встановлений Claude Code CLI у вибраній папці проєкту; модельні запити проходять через FreeLLMAPI.
- Режими агента: планування лише з інструментами читання або Turbo з одноразовим підтвердженням кожного редагування.
- До читання й запису дозволені лише файли папки проєкту; для запиту можна окремо надати доступ до тимчасових копій вкладень.
- Перед підтвердженням редагування можна переглянути шлях, дію та обмежений попередній перегляд змін.
- Unified API key FreeLLMAPI зберігається у системному сховищі облікових даних, а не у файлі налаштувань.
- Передавання вкладень через окрему тимчасову папку; тимчасові копії видаляються після відповіді.
- Збереження історії розмов; останній ліміт вкладень у чаті — 20 МБ.

## Налаштування FreeLLMAPI

У **Налаштуваннях AI** Mnemosyne можна завантажити актуальний офіційний Windows x64 інсталятор або Linux x64 AppImage FreeLLMAPI з GitHub Releases. Mnemosyne перевіряє SHA-256 за метаданими GitHub перед запуском. Після встановлення/запуску відкрийте FreeLLMAPI dashboard, додайте ключі провайдерів із безкоштовним тарифом і скопіюйте unified API key у Mnemosyne. Desktop-збірка FreeLLMAPI зазвичай слухає `http://127.0.0.1:31415`; standalone server — `http://127.0.0.1:3001`.

Для роботи без оплати залишайте в FreeLLMAPI лише безкоштовні провайдери та моделі, а у **Keys → Anthropic** налаштуйте маршрути для сімейств, які використовуватимете в Mnemosyne (Sonnet, Opus, Haiku), наприклад на `auto` або іншу безкоштовну модель. FreeLLMAPI збирає ліміти з підключених ключів відповідно до квот і правил самих провайдерів; додавання кількох акаунтів не гарантує пропорційного збільшення квот.

У чаті можна вибрати, скільки останніх запитів передавати агенту. Старі повідомлення залишаються у локальній історії, але не впливають на контекст, доки не вибрати **Уся історія**.

FreeLLMAPI завантажується як окремий офіційний компонент, а не вбудовується у файл Mnemosyne. Щоб не допустити оплати, у FreeLLMAPI залишайте в fallback chain лише безкоштовні провайдери й не використовуйте платні custom endpoints. Mnemosyne не може гарантувати нульові списання на стороні провайдера; його тариф, квоту й спосіб білінгу треба перевіряти окремо.

Віддалені адреси потребують HTTPS. Ключі не зберігаються у файлі історії чатів.

## Режими агента

- **План · читання**: дозволяє `Read`, `Glob` і `Grep`; Claude не може редагувати файли або виконувати команди.
- **Turbo · підтвердження змін**: дозволяє читання, `Edit` і `Write`; кожне редагування вимагає підтвердження, shell-команди й інші інструменти заблоковані.

Кожне редагування у Turbo проходить через підтвердження Mnemosyne; відмова блокує саме цю операцію. Перевірка шляхів і доступних інструментів є додатковим захистом застосунку, а не системною пісочницею: вона не ізолює процес Claude Code від ОС. Для роботи з недовіреним кодом використовуйте окрему VM або контейнер.

## Запуск із вихідного коду

Потрібні Rust та Cargo. Для роботи потрібні запущений FreeLLMAPI та встановлений Claude Code CLI.

```powershell
cargo run
```

GitHub Actions запускає тести та release-збірку для Windows і Linux після кожного push у `main` та для pull request. Workflow публікує користувацькі пакети `mnemosyne-windows-x86_64.zip` і `mnemosyne-linux-x86_64.tar.gz` як build artifacts. Windows-пакет містить PowerShell-інсталятор; Linux-пакет — інсталятор оболонки користувача та `.desktop`-ярлик. Адміністраторські права не потрібні.

На Windows розпакуй ZIP і запусти `install.ps1` з PowerShell. Якщо Windows заблокує завантажений скрипт, виконай `powershell -ExecutionPolicy Bypass -File .\\install.ps1`. Mnemosyne з'явиться у **Settings → Apps → Installed apps** для поточного користувача; ярлик запуску — у меню Start.

На Linux розпакуй tar.gz та виконай `./install.sh`; для видалення запусти команду `mnemosyne-uninstall`. Якщо `~/.local/bin` ще не в `PATH`, повторно відкрий термінал або виконай `~/.local/bin/mnemosyne-uninstall`. Скрипти видалення прибирають лише програму та її ярлики, не чати, ключі чи папки проєктів.

Linux-пакет не містить системні бібліотеки графічної оболонки; можуть знадобитися залежності `eframe`/`rfd` (GTK, X11/Wayland та аудіосистема).

Історія чатів зберігається у системній локальній папці даних користувача в каталозі `Mnemosyne`.

Переглядач проєкту підтримує Markdown і поширені текстові формати до 2 МБ та зображення до 20 МБ/8 мегапікселів. PDF відкриваються зовнішнім системним переглядачем; перегляд PDF усередині Mnemosyne та спеціалізованих бінарних форматів поки не підтримуються. Markdown відображається як вміст, HTML не виконується, а зображення за зовнішніми URL не завантажуються. Переглядач пропускає каталоги збірки та залежностей і не переходить за символічними посиланнями.
